班班保留本地关键词唤醒，整句识别改为 SenseVoiceSmall INT8，并使用 MeloTTS 中英 VITS 神经女声，沿用现有 ONNX 运行时。模型固定到维护者提交 `2365baeacb507f821a0c8120fcee3d484dba7a07`，约 228.45 MiB，下载与校验脚本为 `scripts/prepare-banban-asr.py`。这与小智后端 `sherpa_onnx_local.py` 的 SenseVoice 路线一致，但班班在 C# 中直接适配，未打包小智的 Python 运行环境。此前 Zipformer 的合成测试通过后仍出现真人误识别，因此已移除，不以合成通过宣称真人准确率。未知词在原生、网页和服务端拦截并要求重说，已有待确认任务保留。

`BanbanSpeechRecognizer.cs` 负责完整音频解码、VAD 断句和有界异步队列；关键词监听保持独立，识别完成前后均检查代次，取消后丢弃旧结果。开头约 800 ms 缓冲和停顿等待用于避免切掉首字或把中英短停顿拆成两条任务。SenseVoice 模型保留 FunASR 模型协议，第三方声明在关于页面和文档中提供。

播报模型来源 [MeloTTS](https://github.com/myshell-ai/MeloTTS) 与 [维护者转换模型](https://huggingface.co/csukuangfj/vits-melo-tts-zh_en)，锁定转换仓库提交 `a0d5c6a264c0ef92d70d8661d8cc502d79627cd6`；下载、压缩与文件校验记录在模型清单和 `scripts/prepare-banban-neural-voice.py`。不使用首次联网下载来补齐声音。

## 保留班班的任务边界

平台和电脑操作继续进入现有权限、确认、取消和真实设备回执。语音服务不另建可绕过检查的工具。停止音频与取消任务是不同动作，已完成的操作不回滚。

原生播放队列与音频采集有界；声学缓存只在内存中，不录制或上传麦克风。服务器仍处理文字和任务，没有新增音频服务或 GPU。语音模式已去掉重复的最终文字请求，但需等当前无工具回合生成完成后才播报，长答案仍有首句等待。全校并发和低性能电脑延迟仍需实际测试。

自然对话默认一两句、先给结果，普通知识不强制查询校园工具；实时数据和操作仍核对工具。“好的”“嗯”等接话保留正在处理或待确认的任务，不代替确认。停播支持“等一下”“别念了”等短句；停播与取消继续分开，取消结果按设备实际状态反馈。

MCP 可作为今后的工具适配接口，现有 Windows UIA、文件/文稿和平台工具无需为接语音而整体替换。没有引入 Python/PySide 电脑客户端或 ESP32 固件，也不据此承诺普通电脑达到专用音箱的远场效果。
