# 创意计划白板小窗实施计划

**目标**：学生在独立小窗中按“表达创意 → 核对提交”完成一份创意；手写、语音和纸条图片可以组合，教室首页持续可操作。

**依据**：2026-11-01 对话确认的范围；手写原稿不识别，说完自动在本机转文字并保留原音，图片经本机裁剪确认后保存和提交。原始全景不进入草稿、日志、邮件。

**架构**：保留现有 WebView2 非模态窗口、班级鉴权、IndexedDB 草稿和创意 API。手写作为现有图片附件提交；裁剪工具只返回确认过的 JPEG；原生桥接复用内置 SenseVoice，后台识别，不新增模型或服务依赖。

**设计**：Operate 模式；沿用 Microsoft YaHei UI 字体链、白色与浅蓝色。页面只保留一处标题，两步进度清楚可见；第一步默认手写，语音与图片补充同一份草稿，转写文字与手打文字共用一个编辑框；第二步核对全部内容、试听和选择署名，可返回修改。底部操作固定在小窗内；触屏操作至少 44 CSS px，原有班级进度和成果入口保留。
