# 班班语音模式选型

2026-10-25～26 的 GitHub 调研与落地记录。当前实现为 **sherpa-onnx 本地关键词唤醒 + SenseVoiceSmall INT8 整句识别 + Windows AEC + Silero VAD + MeloTTS 神经语音 + 班班现有任务引擎**。识别模型及词表约 228.45 MiB，神经语音包约 152 MiB，无需把音频发到服务器。此前流式模型在真人数学句子和中英切换时出现误识别，合成测试通过不能替代真人结果；新模型需重新验收。旧的流式模型已从产品资源移除，不同时携带两套识别模型。使用方式见[班班语音助手](班班语音助手.md)，代码适配见[班班与小智源码对照](班班与小智源码对照.md)。Pipecat 未接入当前版本。

如果将来需要跨平台流式识别、云端全双工语音或独立语音供应商，**Pipecat** 可作为候选实时会话层，继续复用现有班班任务引擎。当前服务端为 Python/aiohttp，网页为原生 JavaScript；接入仍需编写适配层并验证学校网络及声音效果。

| 项目 | 已核实的能力 | 对班班的适用性 |

| [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | 本地语音识别、合成、VAD，支持 Windows、Python、C# 和 JavaScript。代码为 Apache-2.0，模型许可独立。 | 当前已接入 C#：wenetspeech 3.3M 唤醒、SenseVoiceSmall INT8 整句识别；任务规划和电脑操作仍由班班完成。SenseVoice 模型按 FunASR 模型协议分发。 |
| [小智助手](https://github.com/78/xiaozhi-esp32) | 本地 ESP-SR 唤醒、ASR/LLM/TTS 或 Realtime 音频流水线、MCP 设备/云端操作；配合支持 AEC 的硬件可全双工。 | 参考其职责分离及唤醒、对话、打断结构。固件面向 ESP32，不能直接装进当前 Windows 教室端；也不能据此承诺普通电脑麦克风有专用音箱的远场效果。 |

本地声音选用 [MeloTTS](https://github.com/myshell-ai/MeloTTS) 中英 VITS 的 fp32 转换模型（MIT），复用 sherpa-onnx/ONNX。对比中 int8 与 Kokoro 在本机更慢，最终只打包已选择的模型、词表、文本规则与许可；不打包研究模型和未使用的词典。Silero VAD v5 约 2.2 MiB。模型锁定和校验见源码清单及 `scripts/prepare-banban-neural-voice.py`。

以上是文档、源码与本机模型检查结果，没有在教室噪声、远场麦克风或学校网络中做语音效果测试，也不据此承诺延迟、识别率或并发量。神经合成的短语回送小型 ASR 存在错误，技术播放检查通过不代表真人听感或识别准确率通过。

Vercel 官方 AI Gateway 文档提供流式转写（`experimental_streamTranscribe`），可作为将来经用户配置的云端候选。当前项目采用既有 Python/aiohttp 与 Windows 本地语音组件，不需要迁移到 React、部署 Vercel 或把待机音频送到云端。

当前识别模型固定在 [SenseVoice ONNX 转换版本](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/tree/2365baeacb507f821a0c8120fcee3d484dba7a07)，使用语言自动检测与文字规范化。参数对照中关闭规范化会漏掉英文百分数单位，因此保留默认值。此前 Zipformer 的 19 条合成句检查曾通过，但随后真人测试仍出现严重误听，已淘汰；其热词和四路径解码配置不适用于当前 SenseVoice。新的合成检查也不等于真人识别率。

播报打断的现场失败暴露了扬声器回采问题。现接入 [Windows Voice Capture DSP](https://learn.microsoft.com/en-us/windows/win32/medfound/voicecapturedmo) 的 source mode，以系统自带 AEC 同步默认麦克风和扬声器参考信号。原生接口参照 Microsoft 文档与 [Windows 音频示例](https://github.com/microsoft/Windows-classic-samples/tree/main/Samples/Win7Samples/multimedia/audio/aecmicarray)。v10 基准播报测试已抑制自身回音转写，用户随后确认真人说“班班停一下”能立即停止播报；本轮再加入 VAD 与普通插话的识别上下文交接。

## 接入现有班班

```text
教师说话 → 语音识别 → 班班现有会话与任务引擎
                         ↓
                 系统操作 / 教室电脑操作
                         ↓
                  真实回执 → 简短语音回复
```

网页点击麦克风进入连续对话，在原聊天窗口显示识别文字、气泡和操作结果。界面只需呈现“正在听”“思考中”“正在说”等当前状态，底层设备与工具入口继续由自然语言驱动。

识别出的最终话语进入现有 `/api/banban/chat/stream` 会话路径，复用账号权限、分析范围、历史、操作卡和设备回执；不能在语音框架中另建一套可绕过这些检查的电脑控制工具。Pipecat 默认示例中的模型与工具编排需要替换为班班适配器，避免两个代理分别管理同一任务。

播报使用确定的完整短句，不朗读工具过渡文字、技术参数和整张操作卡。工具规划保持静默，额外的禁止工具答复请求产生按序 `speech` 事件，避免朗读会被 `answer_reset` 撤回的草稿；因此多一次模型调用和等待。设备真实完成之前，语音不能提前声称操作完成。

插话时先停止播报并处理新话语；“取消刚才的修改”需要绑定当前待办操作并调用对应取消接口。停止说话、取消规划和已经执行到电脑上的动作是不同状态，不能把停止音频当作电脑操作已回滚。需要确认的操作保留现有确认流程；若支持口头确认，须明确绑定当前操作与内容，不能把背景声或普通回应当成确认。

当前中英识别与合成均使用本地组件，文字模型连接负责理解与任务安排。没有新增语音供应商账号或语音密钥。网页语音仍受浏览器支持与权限限制，正式网页需要 HTTPS；真正的后台唤醒使用 Windows 教室端。

实际验收应覆盖：“高一一班”等口语班名、连续指令、插话、取消、模糊目标澄清、断网恢复和课堂背景声。语音能调用的操作范围，以当前班班引擎实际接入且账号获授权的能力为准。
