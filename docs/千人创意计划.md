# 创意计划

学生可以在教室首页提交班伴与校园软件功能的改进想法。手写、纸条照片、语音、文字任选一种，也可组合；班级由已绑定教室自动填写，姓名选填。

## 使用流程

1. 教室首页顶部、“呼叫班班”左侧点“创意计划”，打开独立小窗。提交分为“表达创意”和“核对提交”两步；手写、语音和纸条图片共同补充一份草稿，入口沿用同排按钮外观，首页不放置独立大卡片。
2. 第一步默认显示手写板，提供画笔、橡皮、撤销和清空，工具有图标、选中状态及对应光标；原稿作为图片直接发送，不识别手写文字。点“说创意”，说完点“结束录音”，自动在本机转文字，同时保留原音。识别结果与旧草稿文字自动显示在同一个可修改的“创意文字”框中，不再单设文字入口。转写失败或取消后仍可提交原录音，或重试转文字。
3. 三个入口为“说创意、拍创意、传创意”，均为白底描边。点“拍创意”，立即在创意小窗中央打开相机取景窗，无需向下滚动；等待权限时也可关闭，失败时可在窗内重试。拍照后关闭相机并进入裁剪；点“传创意”添加本机图片，同样先裁剪，再确认最终预览。拖动边角框住纸张，可展开“精细调整”；确认字迹清楚、范围内没有多余人物后点“使用纸条”，回到原草稿。相机实时预览可能包含周围人物，程序不自动检测纸张或人脸；只有确认后的裁剪图进入草稿与上传，完整画面不写入草稿、日志或邮件。关闭相机或按 Esc 会停止采集并返回拍摄入口；取消、关闭、切页会丢弃未确认的原图。
4. 点底部“下一步”，在同一小窗核对文字、手写原稿、图片并试听录音，选择“不署名”或“署名”；署名时填写或说出名字，点“确认提交”才发送。“返回修改”保留全部内容，修改后可重新核对。已发出但结果未确认的提交直接重试原内容与署名。相机与麦克风不会自动开启；关闭或最小化会停止采集并保存已确认的草稿。页面不放置“返回教室”按钮，可用窗口右上角关闭。
5. 点“本班进度”查看原稿、附件、审核回复与当前状态。待评审的记录可点“删除”，核对标题后确认；已采纳、实现中、已上线和暂不采纳的记录保留。教室电脑由班级共用，本班同学共同查看和删除本班待评审记录，不按署名区分权限。
6. ICe 使用真实登录的超级管理员账号，在教师端“创意计划”统一评审。右侧分为提交信息、原稿附件与评审回复；状态和回复等宽，保存按钮靠右，保存提示位于左侧。AI 建模社参与讨论，由管理员操作。
7. 评审状态为待评审、已采纳、实现中、已上线、暂不采纳。管理员可写回复；是否采纳与是否向全校展示分别设置。
8. 全校成果只展示管理员确认发布的标题、摘要、班级和状态，不公开原始文字、姓名、照片或录音。待评审和暂不采纳的创意不可发布。

创意小窗不隐藏或禁用教室首页，两窗可分别移动，首页仍可操作。重复点击入口会唤起已有小窗并保留当前内容；关闭只结束创意窗口，保存草稿，不中断首页正在进行的早读。默认大小为 720×620 DIP，可调整大小；较窄窗口内通过纵向滚动完成操作。

创意的语音入口统一为“说创意”，不再另设录音页签或第二套正文麦克风。姓名旁保留“说出名字”，识别结果填入当前光标或替换选中文字，可继续修改；这段临时声音不作为创意附件上传，不替换原录音。切页、取消或关闭窗口会停止采集与识别，已确认的草稿继续保留；迟到结果不会填入其他草稿或步骤。本轮范围仅为创意计划小窗。

## 默认限制与保存

- 手打文字与语音文字合计最多 3000 字，姓名最多 40 字。
- 手写原稿与图片合计最多 3 份；有手写时可再附 2 张图片。添加图片支持 JPG、PNG、静态 WebP，输入及处理后每张不超过 2 MiB，最终 JPEG 长边不超过 1600 像素。
- 录音最长 60 秒，上传为 16 kHz、单声道、16 位 PCM WAV，最多 2 MiB。
- 本次媒体合计最多 8 MiB；同一教室一分钟最多提交 3 条，重试同一提交不占新条数。
- 未提交的草稿保存在对应学校、设备和班级的本机浏览器存储中。提交失败后保留原稿并可重试；重复重试同一提交编号只保存一条。
- 删除待评审创意会移除原稿和附件，无法恢复。服务端核对当前班级、状态和版本；确认期间已评审的记录不能删除。仅保留无正文的提交编号，防止旧请求重试使内容重新出现，也不能通过删除绕过每分钟提交限制。删除失败可重试，成功后刷新记录与数量。
- 录音处理失败时保留原录音，可重试保存；创意已经送达但本机草稿清理失败时，显示“已送达”并只重试清理，不重复创建创意。
- 创意和附件单独保存在服务数据库及同级的 `ideas-media` 目录，不参与普通教室来音的 30 分钟清理。备份、迁移时须同时包含数据库与该目录。
- 教室设备只可读取当前绑定班级的原稿和附件；其他教师角色不可读取统一创意箱。超级管理员账号才能评审。
- 两处同时修改同一创意会提示版本冲突，保留编辑稿，核对最新评审后再保存。

## 每日邮件摘要

默认每天北京时间 18:00 汇总新增创意；没有新增时不发。复用教师反馈的 `ICECLASS_FEEDBACK_*` 邮箱配置，不在客户端保存 SMTP 密钥。

摘要包含新增数量、班级、创意标题、状态与编号。照片、录音和完整原稿在教师端查看。邮件发送在后台线程完成；成功后记录批次，失败保留批次等待重试。SMTP 接受邮件后如进程在落盘前异常退出，可能再次投递同一 Message-ID；不承诺跨外部邮件系统的绝对恰好一次。

删除会重建尚未发送的摘要，避免再次包含该创意；正在发送时提示稍后再删，已经发出的邮件无法撤回。

教师端页面显示邮箱是否已配置、上次发送、下次时间及失败提示。`ICECLASS_IDEAS_DIGEST_ENABLED=0` 可停用摘要；本地验收环境显式停用，不向真实邮箱投递演示创意。

## 接口与运行

服务端为既有 aiohttp / SQLite；前端使用既有原生 JavaScript 与 WebView2，无新增运行依赖。设备凭据只在原生层注入同源 `/api/ideas/` 请求，不放入页面地址、JS 状态或表单。

| 用途 | 接口 |
| --- | --- |
| 获取绑定班级 | `GET /api/ideas/student/context` |
| 提交 / 本班记录 | `POST /api/ideas/student` / `GET /api/ideas/student` |
| 删除本班待评审创意 | `DELETE /api/ideas/student/{id}`，JSON：`{"version": 1}` |
| 全校成果 | `GET /api/ideas/showcase` |
| 统一创意箱 / 统计 | `GET /api/ideas/admin` / `GET /api/ideas/admin/summary` |
| 保存评审 | `PATCH /api/ideas/admin/{id}` |
| 原始附件 | `GET /api/ideas/media/{id}` |

摄像头需要实际连接、系统授权及可用的 WebView2；纸张清晰度依赖教室摄像头的距离与对焦。无可用摄像头时仍可使用手写、添加图片或录音。照片、手写不做 OCR。语音转文字复用教室端内置 SenseVoice，不要求另下载模型，不上传到新的识别服务；首次初始化在后台进行，可取消，迟到结果不会覆盖重录的内容。

## 验证入口

- 服务端：在 `server` 目录执行 `python -m unittest test_ideas test_feedback test_app -v`。
- 教师评审页面：`node scripts/test-ideas-admin.cjs`。
- 学生页面：`node scripts/test-ideas-student.cjs`。
- 手写与裁剪：`node --test scripts/test-ideas-ink.cjs scripts/test-ideas-paper.cjs`。
- 本地识别与取消：`tests/ReceiverOfflineChecks` 的 `--ideas-voice-checks`；显式设置 `ICECLASS_IDEAS_VOICE_REAL_MODEL=1` 可运行内置真实模型检查。
- 实际 WebView2 链路：`tests/ReceiverOfflineChecks` 的 `--ideas-browser-checks`，仅接受显式的本地演示绑定。
