# 班班语音防串声

2026-10-27 本地修复，尚未部署正式服务或发布安装包。

原先唤醒后，班班会把活动对话中检测到的人声都当作输入；VAD 只区分语音与静音，不判断是谁在说话。截图中的“嗨小雨”“你在吃什么”分别进入了普通识别和播报中的自然打断路径。用户已确认它们来自旁人，不能用回声消除代替说话人区分。

现在喊“你好班班”时，班班使用最近约两秒的声音建立本次对话的临时比对特征。后续整句、播报中的插话和关键词捷径都先比对说话人，再进入文字识别与操作。未匹配的声音不发送给模型、不显示成用户消息，也不触发“没听清”的回答。原说话人仍可连续安排任务、短答、打断和取消。结束对话、闲置回到待机或关闭语音时清除特征；另一位教师可再次喊唤醒词开启自己的对话。

使用现有 sherpa-onnx 的说话人接口和 CAM++ 中英模型，新增文件 28,281,164 字节（26.97 MiB），单 CPU 推理，不新增 Python、PyTorch、云端推理或服务依赖。音频和比对特征只在本机内存中使用，不上传或保存。SHA-256 和重建方式见模型清单与 `scripts/prepare-banban-speaker.py`。

同时将 Windows 回声消除输出用于待机、普通收听和播报三个状态，避免切换时重新接入未处理的原始麦克风。回声消除暂不可用时沿用原有麦克风路径，说话人比对仍然生效；输入来源变化会清空未完成的音频片段，诊断只记录来源、状态、耗时和被拒绝事件。

验证入口：

```powershell
dotnet run --project tests/ReceiverOfflineChecks -- --speaker-focus-checks output/speaker-focus
dotnet run --project tests/ReceiverOfflineChecks -- --speaker-corpus-checks <公开测试样本目录> output/speaker-corpus
dotnet run --project tests/ReceiverOfflineChecks -- --voice-boundary-checks output/voice-boundaries
```

前一项将两种合成声音直接送入实际的麦克风回调、关键词、VAD 和识别流水线，不启动麦克风或扬声器。第二项使用 sherpa-onnx 示例的公开 `csukuangfj/sr-data` 样本，覆盖同人不同语句和其他说话人；不是用户现场录音。现场仍需在电脑自带麦克风上验证两人轮流说话、本人插话与取消；多人重叠、过远或很短的声音可能无法稳定区分，说话人比对不等于声音分离或身份认证。

本轮结果：19 项说话人流水线检查、3 项公开真人语音比对、53 项原有语音边界检查和 143 项原生离线检查通过。教室端、离线验收程序及教师端构建均为零警告、零错误。原故障和超长语音旁路均先由失败测试复现，再修复验证；证据位于 `output/banban-crosstalk-20261027/`。尚未完成用户和旁人现场双人声学验收，未重新验证未改动的云端业务流程。
