# 致谢名单排版与后台统一维护

用户选择在后台编辑并同步到所有教室。沿用批准样板的三组标题、段落和致谢插画；此前真实实现仍是一段总致谢和逐行名单，本轮修正这一差异。保留原名单、顺序、微软雅黑、液态玻璃及现有关于窗口尺寸。

## 实现

1. 共用一份默认内容 JSON，供服务和两端原生程序读取。每组含标题和多行纯文字，分组顺序即展示顺序。
2. 新增持久化致谢配置及只读接口；仅超级管理员能保存，沿用登录、CSRF、审计与 revision 冲突保护。处理器声明班班读写能力。
3. 在账号设置新增折叠的致谢编辑器，支持修改、添加、删除、调整分组顺序和实时文字预览；明确保存后下次打开关于时更新。失败和冲突保留本地编辑。
4. 教室端及教师端打开关于时读取当前平台内容，按样板渲染分组。网络失败保留按平台隔离的上次内容，无缓存使用随程序的默认内容。关闭窗口取消请求。

## 验证

- 先验证缺失功能的失败测试，再实现权限、校验、持久化、版本冲突与跨设备读取。
- 验证客户端更新、离线缓存、平台隔离、坏响应及取消，检查关于窗口 740×660 和 600×500 的换行、滚动与页签。
- 后台检查桌面和窄屏、键盘、保存失败及冲突。构建两端，并检查实际本地教室端致谢窗口。
- 本地使用隔离服务，不修改正式服务或名单，不提交、推送或发布。旧客户端需更新后才支持动态名单。
