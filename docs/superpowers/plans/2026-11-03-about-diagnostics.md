# 关于与诊断实现计划

**Goal:** 交付 2.5.6 的更新记录、可查看/导出/提交的诊断入口、服务器集中日志及每周清理，并调查教室通知动画异常。
**Architecture:** 沿用 AboutContent 共享布局；两端各自收集状态，共享脱敏和诊断 ZIP。已有教师反馈收集继续复用。自动错误批次有界保存在本机，绑定当前登录或教室身份；服务器通过现有身份体系接收，账号设置内按需查看。清理接入原每小时维护任务。动画在真实原生窗口的通知生命周期上验证。
**Tech Stack:** .NET 8 / Avalonia 11.2.5 / 现有 WebView2，不增加依赖。
**Spec:** ../specs/2026-11-03-about-diagnostics-design.md

## 约束与检查重点

- 保留现有未提交改动、绑定、设置、发布包和回退资料；不提交或推送 Git。用户要求服务器集中日志与每周清理，相关服务端与网页在备份、数据副本演练后部署；客户端 2.5.6 提供本地安装验收。
- 保留 Microsoft YaHei UI、SemiBold 与原窗口尺寸，新增页签支持键盘与滚动。
- 文件缺失/读取失败、关闭时取消、重复点击、窄窗口和凭据脱敏必须验证。
- Windows 动画偏好与实际动画播放分别记录；学校硬件无法本地代验。

## 步骤

1. 在 tests/NativeAnimationChecks 添加关于入口缺失与实际通知生命周期检查，先确认失败或复现结果。
2. 增加 Shared/SupportDiagnostics.cs，复用教师端现有脱敏规则与有限日志读取；添加 ZIP 脱敏和内容回归。
3. 增加 Receiver/AboutDiagnosticsView.cs 与 AboutReleaseNotes.cs；AboutContent 添加两页，教师端与教室端接入各自收集函数。
4. 诊断中加入通知动画、资源、更新及环境状态；只有证实动画原因后修改动画路径。
5. 两端版本升至 2.5.6，自动按分钟合并、脱敏和限量上报错误，完整近期日志由本人手动提交；服务端再次脱敏并限制容量。
6. 超级管理员在“账号设置 → 客户端日志”筛选、翻页、读取详情和复制；普通教师不能读取。上报与读取处理器按班班功能接入规范声明。
7. 上海时区每周一 03:00 起的首次既有维护轮次，批量清理超过 7 天的客户端诊断；维护周次落库，停机后可补做。只操作新增诊断表。
8. 核对登录/绑定变化、同绑定重连、断网重试、响应丢失去重、退出与重启续传；不将旧身份的待发错误归入新身份。
9. 运行受影响检查及原生/网页交互验收，生成本地轻量包，打开最新界面。

使用 `.tools/desktop-sdk/runtime/dotnet.exe`，所有中间产物放入 `output/diagnostics-2.5.6-20261103/` 独立目录。运行 DesktopChecks、ReceiverOfflineChecks 的关键检查及 NativeAnimationChecks；记录实际结果、导出文件和未验证的学校现场条件。
