# 创意工坊：纸卡答题设计

日期：2026-11-15。范围：产品与接入设计，尚未实现或进行摄像头验收。前八项由用户逐项确认；其余细节按用户“接下来的题都按你想的来”的授权由助手选择，文中分别标明。

## 目标

在 ICeClass 创意工坊增加“纸卡答题”，实现 Plickers 式课堂收答，并参考 OurClass / ourclass-lite 的题目、提交和教学分析模型。学生使用纸卡，教师可用教室摄像头或手机采集；同一套名单、纸卡和课堂记录贯通两种采集入口。

支持两种出题方式：现有 PPT、课本或口头提问配合临时收答；课前在 ICeClass 录题、组卷，上课按题收答。两种方式进入相同的答题和统计模型。分析参考主要指 ourclass-lite 的题目、提交和知识点口径，不引入学生扫码打开练习网页的流程。

## 用户已经确认

| 事项 | 决定 |
| --- | --- |
| 纸卡 | ICeClass 生成并打印新卡，首版不以现成 Plickers 卡兼容为要求。 |
| PPT 配合 | PPT 照常使用，教师手动开始、结束每题收答。 |
| 记录与分析 | 按学生保存逐题结果，提供课后查看及跨课分析。 |
| 首版题型 | 单选、判断。 |
| 网络 | 手机联动需要联网；白板本机扫描可离线保存，恢复后同步。 |
| 标准答案 | 收答前、收答后和课后均可设置；尚未设置时不计算正确率。 |
| 临时题补录 | 题目内容与知识点可课后补；未标知识点的题仍有答题统计。 |
| 纸卡分配 | 同班卡号固定对应学生，允许补印和换号，历史记录保持原归属。 |

## 接入事实与方案选择

本轮代码依据：

- `web_controller/homework/classroom/home.js` 的工坊入口仍为筹备占位；已有创意计划是另一个业务。这里建立工坊项目入口，保留其他现有入口，不把创意计划误作纸卡模块。
- `server/homework.py` 提供按班级维护的学生 ID、姓名及名单版本；`server/permissions.py` 提供真实班级授权。
- `Receiver/StudentVoiceWindow.cs` 已用本地资源和 WebView2 虚拟 HTTPS 域加载教室首页，但当前页面设备权限全部拒绝。
- `Receiver/ReadingOutbox.cs` 已有写入后刷新到磁盘、按记录编号去重及补传失败保留的实现模式；它保存的是早读业务，不能把答题数据混入其早读队列。
- `server/app.py` 的 `Rooms` 提供按班级的设备 WebSocket；现有普通消息还有 4096 字符限制，不能认为新增答题消息已能直接通过。按班级广播也不能替代发往本场次所属设备的定向传输。
- `server/requirements.txt` 当前仅声明 aiohttp。学校服务器不增加 OpenCV 摄像头循环；原生端也不为本功能引入 Python 运行环境。

| 路线 | 取舍 |
| --- | --- |
| 采用：共用 JavaScript 本机识别，白板使用 WebView2，手机使用 HTTPS 网页 | 与当前技术栈匹配，可覆盖两种采集入口。白板统一确认课堂收答，手机只传识别结果和受限控制命令。 |
| 原生 Android 扫描端 | 中文 QuizScanner 有参考，但需要新建构建、签名、分发和真机维护链路。首版先验证网页；若网页在目标设备上无法达标，再根据实测决定。 |
| 把视频传到学校服务器识别 | 增加持续带宽、视频处理依赖和服务器负载，与本机可识别的目标不符。 |

采用路线是助手在授权范围内的选择，不能表述为用户已经指定识别库或原生实现。

## 日常使用

### 备课与纸卡

教师工作台增加本功能管理入口，复用当前登录和可访问班级。班主任及原有名单管理权限负责名单与固定卡号；任课教师使用授权班级的现有卡号，不在每次开课时重新发号。

首次生成卡号时，按当时名单顺序一次分配并保存映射，后续重排名单不会重新编号。不同班级可以复用相同编号的纸卡；一次课堂只对应一个班级。补印保留卡号；更换卡号显式更新映射，已开始的课堂使用其原快照。被换出的旧卡在新课堂提示无绑定，不自动指向别的学生。

卡片带清楚的编号及 A/B/C/D 方向标记，支持整班 PDF 打印和单卡补印。判断题固定 A=正确、B=错误，C/D 不作为有效作答。打印模块与检测模块共用同一套编码和方向规则。

首选验证 QCMCam2 默认 `QCMCAM_4X4_157h3` 字典，产品内标记为 ICeClass 纸卡第一版。正式发卡前冻结字典、编号映射和方向，并通过往返识别验证。这套候选字典提供 157 个编号；班级人数超出可用编号时明确提示，不能重复分配或只给部分学生发卡。该容量不代表同屏可可靠识别 157 张卡。后续改变卡集须明确新卡版本，不能让已发纸卡默默失效。

### 配合现有 PPT

教师打开 PPT，在 ICeClass 选择班级和学科后开课。已有 Windows 教室端提供可收起的小控制窗，手动新建临时题、开始收答、结束收答和查看结果，不读取 PPT 内部结构，也不自动跟随翻页。

临时题起初只需要本场次中的题号和题型，题干、标准答案及知识点可以暂缺。标准答案通过教室控制区或已配对手机设置；设置答案不等于向学生公布答案。

### 使用预录题目

题目支持文字及 PNG/JPEG/WebP 图片；选项可填写文字，也可由题目图片承载，仍需明确有效选项范围。单选为 A-D 中连续的 2-4 个选项，判断为 A/B。标准答案可暂空，知识点标签可暂空。

教师把题目组成有序课堂题单，选择班级开课。题目和所用图片在教室端缓存完成后，才标为可离线使用。未缓存的图片明确显示不可离线，不用空白内容冒充就绪。

题库、题单及附件默认仅作者可读写；拥有某班权限不等于可以浏览其他教师的私有题库。作者可另存副本用于改编。首版提供手工录题和整题图片导入，不把自动解析 PPT、PDF 或 OCR 作为必经流程，也不导入可执行 HTML 练习。

作者在教师工作台选择有权班级，将题单的固定版本快照发布到该班。教室端凭本班设备绑定只读下载已发布题单，不浏览教师完整题库；缓存完成后可离线开课。发布后的班级题单可由该班有权教师使用，课堂题目快照和报告沿用班级权限；教师可将有权查看的快照另存为自己的新题目，取得新题目 ID，不获得原题的编辑权。首版不增加全校公共题库或跨班分享系统。

源题修改不会自动替换已发布快照；教师显式重新发布后供以后课堂使用。撤回发布在设备联网获知后停止新开课，不能承诺实时撤回离线缓存；已开始课堂的快照和历史记录仍保留。

### 手机与白板

同一场次始终有一个所属 Windows 教室端。该教室端可以使用本机摄像头，也可以接收一个当前配对手机的识别结果。手机模式要求手机、教室端均能连到学校服务，可以使用不同网络，不要求同一 Wi-Fi。首版不提供脱离教室端的手机独立课堂。

手机扫描配对码、登录原有教师账号并通过班级权限校验后加入，页面提供后置相机预览、当前题号、已收人数和开始/结束/下一题控制。控制命令同样由教室端确认，不在手机另建课堂状态机。

每次只启用一个采集来源。切换白板/手机或更换手机在当前轮次结束后进行；旧来源立即失效。手机断线时保留已确认答案，手机显示连接中断和待确认数量，不把继续对准纸卡显示成收答成功。教师可在白板结束当前轮次，再切换本机继续下一轮；同题继续作为明确的新轮次保留。

## 助手确定的收答规则

| 问题 | 默认规则 |
| --- | --- |
| 何时计入 | 同一卡号与方向通过稳定确认，且对应当前班级、当前轮次和当前采集来源后才计入。 |
| 学生改答案 | 收答期间允许修改，使用最后一次稳定且已确认的答案；改答同样需要稳定确认。 |
| 消失与遮挡 | 纸卡移出画面不撤销已收答案；再次出现且答案相同不重复计数。 |
| 同号重复 | 先检查去重前的全部候选；同号同向合并，同号不同方向时不采用该帧，提示重复卡并等待新读数；不能先任取一个候选而丢掉冲突。 |
| 未知或无效卡 | 不加入名单，提示未绑定或无效选项，教师可以核对卡号。 |
| 停止收答 | 立即封存已经确认保存的结果；尚未确认的候选或迟到消息不自动补入。 |
| 重开同题 | 创建新的收答轮次，保留原轮次；本课默认统计使用最近一次已结束封存的正式轮次，不逐人回退到旧轮次补答案。新轮无人作答也按本轮未作答展示。 |
| 已公布后的重答 | 标为讲解后练习，保留记录，默认与正式答题统计分开。 |
| 公布内容 | 收答期间大屏默认只显示已收人数；结束后教师主动展示选项分布，再主动揭晓标准答案。 |
| 个人结果 | 只在真实登录且有本班权限的教师工作台查看，支持手机浏览器；教室端仅提供本课匿名汇总，不提供逐人报告或排名。 |

借鉴 QCMCam2 的方向边界死区、滑动窗口及精确/纠错读数加权，具体参数以其固定源码和目标设备实测为起点。候选识别状态和实际已收状态分开显示。方向不明确、低质量或互相矛盾的读数不会直接覆盖已确认答案。

ICeClass 内揭晓答案后，后续重答自动标为练习。若答案通过 PPT 或口头公布，由教师在重答前标记“已讲解”；不自动判断外部课件是否已经给出答案。练习轮不替代本课正式轮次。

不承诺理论字典容量、源码检测调度间隔就是实际识别人数或时延。白板固定机位的后排覆盖、手机横竖屏与镜像需要分别验证；镜像只用于预览，判读使用一致的未镜像坐标规则。

## 数据模型

各实体只承担当前业务需要，不另建通用测验平台。

| 实体 | 必要内容与边界 |
| --- | --- |
| 卡号绑定 | 班级 ID、稳定学生 ID、卡集版本、卡号及映射版本；同班有效卡号唯一。 |
| 题库题目 | 稳定题目 ID、版本、作者、学科、题型、题干/图片、有效选项、可空标准答案及知识点标签。 |
| 课堂场次 | 场次 ID、班级、学科、所属设备、发起教师（可空）、时间、名单和卡号快照、同步状态。 |
| 课堂题目 | 本场题号、可空的题库题目引用、题目版本快照、可后补的题干、标准答案、标签及修订版本。 |
| 收答轮次 | 独立轮次 ID、课堂题目、正式/练习用途、采集来源及其代次、开始/结束、已封存状态。 |
| 答题记录 | 轮次、稳定学生 ID、当时姓名及卡号、最终确认选项、确认顺序和来源；轮次内每人一份最终结果。 |
| 课堂修订 | 操作来源（设备或已验证教师）、时间、修改字段和前后值，用于答案/标签/归属等实际更正；不复制保存每帧识别图像。 |

学生长期查询键为班级 ID + 学生 ID。重名不合并，名单重排不换人，删除或重命名学生不改写历史快照。跨班转入不靠同名自动串联档案；首版报告按各自班级身份展示。

课堂复制题库快照，后续修改题库不会回写历史课堂。课堂进行中，轮次之间的本场答案及题目信息修改经教室控制区或已配对手机提交，由教室端统一校验版本并落盘；教师工作台对进行中的场次只读。已有作答的题型和有效选项范围锁定，改变它们须新建课堂题目。

课后补题或更正答案修改本场课堂题目，经过权限和版本检查后重新计算派生结果，保留原作答及修订记录；“保存到题库”是单独的明确动作。已结束课堂的记录同步完成后，教师工作台才开放课后修订，避免与未同步本机版本相互覆盖。

## 统计口径

每轮默认全班应答；教师可把实际缺席或免答标记为本轮不应答，变化保留记录，不修改全校考勤或作业数据。未扫描到不能自动当作缺席。标记不应答后保留其已收选项供教师核对，但该学生不计入本轮 N、R、C 和知识点样本；恢复应答后重新纳入，避免参与率超过 100%。

设 N 为本轮应答人数，R 为有效作答人数，C 为其中答对人数：

| 指标 | 规则 |
| --- | --- |
| 参与率 | R / N，N 为 0 时显示“暂无应答学生”。 |
| 已答正确率 | C / R，须已设标准答案；R 为 0 时显示“暂无作答”。 |
| 选项分布 | 每个有效选项的人数及占有效作答人数的比例，另列未作答人数。 |
| 未作答 | 不伪造选项，不直接归为答错；个人记录单独展示。 |
| 未判定 | 没有标准答案，保留选项，不纳入正确率。 |
| 知识点表现 | 只包含已有标签、标准答案和有效作答的题，显示题数、作答数及正确率，不直接命名为“掌握率”。 |

报告提供课堂总览、逐题分布、个人答题明细、按学科/知识点的跨课统计和 CSV 导出。首版按题对错统计，不引入复杂分值、排名或自动积分。

知识点使用按学科组织的平铺标签，教师手动维护和确认，不自动推断。多标签题在各标签中各计一次，总体统计不重复加计。无标签题仍出现在逐题和个人报告中。

跨课知识点概览先按各课选定的正式轮次取记录，再对同一学生、同一题库题目的同一版本取最近一次有合法选项且属于应答范围的作答，避免反复刷同题增加样本权重。若这条最近作答尚无标准答案，则显示未判定、排除正确率，不回退挑选旧的已判定结果；仅新课未作答不会抹去以前的有效作答。最近以课堂时间为准，不以离线记录上传的先后为准。历次课堂记录和按课趋势仍完整保留。

临时题各自独立，不靠截图相似度或相同文字自动合题。只有教师明确关联同一题目时才按同题口径聚合；关联同样属于有记录的修订。

## 本机确认、补传和恢复

白板作为本场次采集数据的单一确认端，既服务本机扫描，也确认手机请求。学校服务器负责教师权限、手机消息转发、已同步记录及课后分析；不接收视频进行识别。

1. 检测器只提交稳定的卡号与选项，不逐帧发送视频。白板把有效变化与课堂控制按一个顺序处理，保存到本机后才返回“本机已收”。手机收到学校服务的中转回执，不等于答案已收。
2. 来源请求携带唯一请求编号、场次、轮次和采集来源代次；白板分配递增确认序号。重复请求返回原结果，相同编号不同内容拒绝。先查已处理请求，再决定尚未处理请求是否因轮次结束而拒绝。
3. 结束收答与答案更新进入同一处理序列；封存只包含此前确认保存的答案。已结束轮次的新请求明确拒绝，不靠手机时间戳给迟到答案补签。
4. 换题、换采集来源、暂停恢复和教室进程恢复都会使旧的采集许可失效；对应代次要保存。旧代次尚未处理的消息即使延迟到达也不能修改新状态。已确认请求仍可查询原回执。
5. 本机采用现有可靠文件写入与补传模式，持久化课堂上下文、最终答案、必要的变化批次和已处理请求回执。可合并小批次降低磁盘写入频率，但确认只能发生在该批实际落盘之后。
6. 补传按所属设备、班级、场次和确认序号校验并去重；缺少前序批次不能宣称整课同步完成。“本机已收”“待同步”“已同步”“需核对”是不同状态。
7. 教室端异常重启后恢复名单、卡号、已确认结果和补传队列，当前轮次进入暂停状态，由现场继续操作后才重新采集；不自动打开摄像头，也不自动接收重启前的未确认请求。
8. 离线使用要求本机已有有效的原班级绑定和缓存名单；没有名单或所选题目缓存时提示先联网初始化。离线新课堂允许不填写教师归属，保留设备来源，联网后由有权教师补充；不缓存教师密码来模拟登录。
9. 改绑或撤销授权后，旧记录保持原服务地址、设备与班级归属。服务端拒绝的数据转入需核对状态，不串到新班级，也不反复重试或直接删除。
10. 结束课堂后本机封存采集记录。同步完成后，教师工作台接管课后修订；设备对旧批次的重试仅按原内容幂等确认，不能覆盖后续教师修订。

手机断线暂停发送新候选，仅保留尚未得到白板回执的请求用于状态核对。恢复后先核对当前场次、轮次、采集许可和请求回执；已变更轮次的旧候选不补到新题。手机刷新或被系统回收前未得到白板确认的内容不承诺恢复；已确认结果以白板本机保存为准。

缓存、存储空间不足或写入失败时不能继续显示收答成功；保留当前可恢复状态并明确提示。损坏记录保留供核对，不擅自清理。

## 权限、配对和设备

- 新教师读写接口在实际处理器声明 `teacher_read` / `teacher_action`，复用真实登录、现有班级权限、版本检查和班班路由发现；不另列一套绕过校验的模型操作清单。
- 已绑定的教室端允许现场执行本场收答控制、新建临时题、设置本场标准答案和题目信息、查看匿名汇总，离线同样可用；本机操作权来自本班设备绑定，不冒充教师登录。无教师身份的操作只记录设备来源，后续教师认领保留认领时间，不把此前操作追记为该教师本人所做。教室端不开放逐人报告、跨课个人分析或私有题库浏览，也不新增离线教师认证体系。
- 教室设备协议只处理本设备所属班级、场次和采集结果，不能借设备凭据访问教师题库管理或全校个人报告。
- 配对码为 5 分钟内有效的一次性随机凭证，不携带长期设备令牌或教师令牌。手机还须真实教师登录和本班权限校验；不能仅因同一局域网便自动授予教师身份。
- 手机配对仅限本场次及一个当前手机，随课堂结束、踢出、权限撤销或教师登录会话失效而终止，最长 4 小时后须重新配对。重连重新检查权限，不永久复用旧二维码。
- 手机控制命令只覆盖本场次的开收答、结束、下一题及轮次之间的本场答案和题目信息设置；不直接修改教师题库。白板所有者和配对关系均须服务端验证，修改仍由白板确认。
- 中转消息必须定向发给所属设备，不把私密名单、逐人选项、标准答案或配对凭证广播给全班设备。新增 WebSocket 消息有显式类型、尺寸、数量及速率边界，不能全局放宽原消息限制。
- 投影视图与教师视图分别组织返回数据，揭晓前不把标准答案下发投影视图后仅用 CSS 隐藏。标准答案修改不触发自动公开。
- 扫描视频仅在采集设备内处理；不保存视频、教室照片或人脸特征，不调用 AI 识别纸卡。教师主动导入的题目图片按题目附件管理。
- 摄像头由用户主动开启，退出扫码、切换来源、撤权或关闭课堂及时停止。WebView2 只对受控扫描页、正确来源和相机权限放行，其他页面和设备权限保持原策略。
- 手机页面通过 HTTPS 获取摄像头权限；白板使用现有虚拟 HTTPS 本地资源机制，不用普通局域网 HTTP 假设解决手机相机权限。
- 适用白板为能运行当前 Windows 教室端且有可用摄像头的设备；不由“希沃”品牌推断 Windows 系统、内置相机或全班覆盖能力。没有合适相机时用手机采集。
- 答题记录按用户要求持续保存，沿用学校备份与权限管理；本功能不新增按天自动清理长期成绩的任务。

## 实现边界与参考代码

优先提取和适配 QCMCam2 的检测、方向、稳定确认及纸卡生成模块，保留具体文件声明，不整体引入 Svelte 应用、CKEditor、原站 PeerJS/STUN/TURN 或上游自有服务地址。QCMCam2 根目录、检测库文件与编辑器依赖适用许可不同，逐文件对照现有第三方声明维护。

参考 ourclass-lite 的题目、提交和知识点统计关系；判分由 ICeClass 根据教师确认的标准答案计算，不接受扫描端上报 `is_correct` 作为可信结果。中文 QuizScanner 的安卓图像方向处理与轮次校验仅作补充参考，首版不新增 APK 工程。

实现触点预计包括工坊/教师工作台页面、两端共用 JS 检测与卡片生成、教室原生控制窗及本机保存、学校服务题库/课堂/分析与设备中转、新功能测试及第三方声明。具体文件拆分和接口路径由实施时依现有组织确定，不在设计阶段创建空模块。

正式打印前验证字典、图案、编号、旋转方向和纠错边界，避免先发卡后换算法。选定库之后再评估是否需要 Worker；当前设计不预设额外框架、OpenCV.js 或新服务器依赖。

## 验收范围

以下是将来实现需要通过的检查，本设计稿不表示已经通过：

1. 两种出题方式和两种采集入口均能完成开课、收答、结束、查看报告；PPT 原有翻页和播放不受控制窗抢焦点影响。
2. 打印与扫描同卡集同方向；真实打印的各方向和判断题 A/B 正确，非法选项、重复卡、未绑定卡和歧义读数不污染结果。
3. 对目标希沃设备、外接相机及实际 Android/iPhone 浏览器，记录纸张尺寸、机位、后排距离、光照、同时可读数量、漏读误读、改答延迟和持续 CPU/内存；真实教室结果决定发布边界，不用字典容量代替效果。
4. 稳定确认、改答、纸卡消失、重复消息、关闭瞬间、换题、换来源、旧代次、已揭晓后重答都遵守轮次规则。
5. 白板离线新建、断线期间落盘、进程重启、磁盘错误、重复补传、缺序批次、改绑和服务端拒绝均不丢已确认结果、不串班、不覆盖云端修订。
6. 手机中转成功而白板未确认时不显示已收；确认后回执丢失可查询；旧轮次未确认请求恢复后不会写入新题。
7. 未作答、缺席/免答、未判定和答错区分正确；已有作答后免答及恢复不破坏人数口径；缺标签不计知识点；多标签、重答、同题复练及临时题关联不重复加权，最近未判定不回退挑选历史成绩。
8. 标准答案、题目内容和标签补录可更新分析并保留修订；题库修改不回写已上课堂；重名、换号、名单重排与学生离班不改历史归属。
9. 手机教师鉴权、班级权限、一次性配对、错误设备、撤权、过期和私密/投影数据边界覆盖真实处理器；离线本机控制不开放个人报告，设备不读取私有题库，班级发布/缓存范围正确；班班发现新业务而不执行私密配对。
10. 正常/窄窗口、触屏、键盘焦点、状态反馈、文字截断、高对比度、减少动态效果及相机释放均检查；延续现有字体、蓝白玻璃和焦点资源。
