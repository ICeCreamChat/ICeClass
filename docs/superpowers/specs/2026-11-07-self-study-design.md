# 晚自习管理设计

用户已要求开始完整实现。目标是第二节晚自习先提醒、持续异常再通知班主任，值班教师无需日常操作。现有教室端使用 Avalonia/C#、WebView2、NAudio、Silero VAD、SenseVoice；教师工作台和服务使用原生 JavaScript 与 aiohttp/SQLite。

## 已确认

- 场景是少数学生零星交谈，必须考虑老师讲题和正常问答。
- 教室电脑摄像头可覆盖全班。已有学校告知和授权；每次拍摄不弹预览，不隐藏设备、操作系统自身的指示。
- 优先减少误提醒；不确定不拍照、不上报。照片供教师核实，不自动判断个人责任。
- 用户要求低 token 成本，自行人工验收，不使用 computer use。

## 方案与边界

已讨论声量提醒、分级告警、值班教师确认、事件附图和课后复盘。采用分级告警，去掉值班老师逐次确认；照片仅在提醒后仍出现独立异常窗口时申请一次。声量不是分贝，声音检测和语义分类不等于识别学生身份。

教室端入口在“班级管理”中，与作业统计并列，查看状态和暂停本节。教师工作台沿用已有样式，新增班级选择、启用/授权、费用上限、运行状态、事件列表、照片查看和误报处理。

用户已确认内置模块、少量疑似文字可交给现有 AI。时间直接由教师端教室浮岛周课表的第二节晚自习派生，复用轮值、调课、停课，不再维护独立星期和时间。默认关闭，云端复核需班主任明确开启。

## 端到端行为

1. 教室端获取当前班级已启用且完成授权的日程，时段外、锁屏、休眠、解绑、关闭、配置过期立即停止采集并清空临时片段。
2. 本地 VAD 筛选反复人声，使用现有 SenseVoice 临时转写有限片段；原始音频不上传、不落盘，不做声纹或学生身份识别。
3. 云端复核需单独启用，仅接收有限短文本和统计。请求没有聊天历史、工具、照片或音频。分类只有 teaching/study/chat/unknown，模糊和学习问答放行。
4. 明确疑似聊天先请求显示悬浮岛提醒。教室端确认实际展示后，新的独立观察窗口再次判为聊天才升级，不能用提醒前片段重复升级。
5. 每个事件只报一次；升级时只申请一次摄像头，立即关闭。失败如实记录，不重试拍摄。教师侧可查看、处理及标记误报。
6. 同班多设备共用预算与事件，配置版本和设备凭据每次重新核验；不跨班读取设置或照片。

## 费用规则（本轮工程默认，非用户指定额度）

- 每班每天默认最多 4 次 AI 请求，默认总 token 上限 2400；教师可向下调整。
- 单次输出最多 64 token，输入 UTF-8 内容有硬限制；先保守预占预算，再记录提供方报告的实际用量。
- 超时、失败、用量缺失保留预占，不自动重试；同一个观察编号重复请求不再次付费。
- 禁用、重启、重新启用或新增设备不重置当天预算。达到上限暂停复核，并明确显示状态。
- 默认沿用班主任已选择的模型连接，不切换到更昂贵的模型。

## 保留与验证

照片默认保留 24 小时，事件和用量保留 7 天；不存转写正文。照片仅向该班班主任及其管理范围内的上级开放。教师工作台自动刷新并显示未处理数量；后台资源在登出和隐藏时按现有模式释放。

测试覆盖权限、版本冲突、日程边界、重复/并发、预算持久化、AI 错误/模糊/讲题、真实展示回执、独立的后续窗口、照片访问与过期、设备停止、UI 保存失败和窄屏。模型判断准确性、后排拾音、真实相机以及学校网络效果必须在真实教室验收，模拟测试不代替现场效果。
