# 班班统一管家

用户已确认：班班是教师端的统一管家；现有功能应可查询和代操作，新功能上线后自动进入能力目录。执行仍受当前账号权限约束，重要修改需要确认，结果以实际业务回执为准。本轮按用户“现在开始操作”继续实现，不提交、推送或部署线上。

## 实现方向

沿用现有 Python/aiohttp 服务、原生教师端和网页界面。采用**功能声明与路由一起注册**：业务模块声明操作名称、输入字段、查询条件、权限、确认要求及执行形式；班班按当前应用的注册结果生成目录和工具参数。界面继续调用原业务路由，班班调用同一处理器，避免维护两套业务逻辑。

考虑过自动猜测任意 HTTP 接口和继续扩充独立操作清单。前者没有可靠的权限、参数和交互语义，后者会继续遗漏新功能。采用显式声明、运行时自动发现，并用覆盖测试要求教师端新增接口明确接入或说明其必须手动完成的环节。

## 服务端能力

- 保留已有操作编号及持久化记录的可读性，迁移已有 18 项操作到功能注册处。
- 自动生成可查询资源和可执行操作列表；新增功能的测试路由不修改班班核心也能被发现和执行。
- 补齐创意列表/汇总/评审/公开，学校浮岛默认规则，绑定码和账号授权、统计与记录导出等现有教师端业务。
- 复用已有角色、班级授权、CSRF、版本冲突、确认、审计与幂等逻辑；在确认时再次核对权限和版本。
- 文件导出返回同源、需登录的下载入口；文件导入由老师选择文件并核对预览，原文件不交给模型、不存进聊天或操作历史。
- 录音内容、登录凭据、密码和密钥保持在现有私密输入或人工处理流程内。班班可以打开相关界面并指导完成，不将“窗口打开”报告成“已发送/已保存”。

## 教师端本机能力

建立受限的教师端原生操作桥，原生功能注册一次后可向网页报告能力清单。至少接入桌面设置、刷新、关于、反馈和更新检查；能直接修改的本机设置提供明确参数和读回校验，发送反馈仍经原表单由老师确认。

网页将实际宿主能力随本轮任务发送给服务端。班班为本机操作建立当前账号的操作记录，网页只执行本轮实时收到且尚未执行的命令，回报真实结果后班班才能继续。历史记录恢复不触发操作；同一命令不重复执行；跨来源、登出或关闭窗口后拒绝执行。普通浏览器没有原生能力时明确反馈，并保留可用的网页操作入口。

## 界面与验证

沿用现有浅蓝主题和紧凑确认卡，只增加必要的选文件、下载、私密输入及本机操作状态。支持键盘、窄窗口和错误反馈。

验证自动发现、新功能注册覆盖、角色/班级权限、确认前后撤权、重复请求、版本冲突、创意处理、文件流程和本机回执。真实模型仅使用本地已有连接及隔离数据，不向正式班级发送消息，不发真实反馈邮件。通过构建和必要检查后，打开最新本地教师端，保留现有绑定与资料供用户验收。
