# 班班通用电脑助手 · 本地验收

2026-10-27。本轮沿用 Python/aiohttp、C#/.NET、Avalonia 和 Windows UI Automation。全局规则来自 `C:\Users\ICe\.codex\AGENTS.md`，同时遵循项目 `AGENTS.md`。仅更新本地验收环境，未提交、推送、发布安装包或更新正式服务器。

## 本轮能力

班班可以根据当前应用公开的控件理解页面，连续完成多步任务。无需给每个应用单独编写“某按钮在哪里”的规则，也不要求用户查找工具编号。用户仍直接在班班对话中安排任务。

- 读取当前界面的文字、输入框值、选项、勾选、展开、滚动和滑块状态。
- 填写输入框、选择页签或选项、设置勾选状态、调整滑块、展开收起、滚动和操作按钮。
- 向已观察并获得焦点的具体控件发送标准导航键，用于未提供完整控件模式的列表或树。
- 操作后重新观察界面、当前窗口和新出现的对话框；旧页面的控件不能继续接收输入。
- 按明确的结果文字等待应用完成。长文本和长输入值可以按关键词定位，回执保留相关片段，避免整段发送。
- 通过 Windows 标准 App Paths 发现已注册的桌面应用。此次本机实际发现 47 个应用；“可发现”不代表每个应用的全部功能都已验收。

保留原有的希沃启动与窗口识别、PowerPoint/WPS 放映、文稿读写、后台唤醒、连续对话、播报和打断逻辑。本轮没有新增语音模型、视觉模型、NuGet/pip/npm 依赖或额外常驻框架。

## 修复的共性问题

1. **回执被丢弃。** 设备通道原来丢弃超过 4,096 字符的消息，导致详细控件快照已经在电脑端完成，模型却收不到。命令回执现可通过较大的接收上限，其他消息继续保留原限制；操作结果仍受 48 KB 限制。
2. **旧观察被缓存。** 同一轮中的再次查看现在读取实时状态。收到新的界面观察后，用户要求的下一次滚动或翻页可以执行；没有新观察时不会盲目重放同一个修改。
3. **把调用当成功。** 按钮点击本身不算保存或提交成功。状态写入须读回，业务按钮须结合结果文字或新窗口核对；未确认时如实说明。
4. **弹窗关闭被误报失败。** 按钮关闭自身窗口后，返回当前窗口列表，供班班继续判断。
5. **长提示无法查找。** 结果匹配使用包含关键词的有界片段，不再只能匹配文字开头。

控件快照最多返回 60 项、扫描 800 个节点、深度 14，文字预算约 4,000 字符。密码字段及其子树不进入快照。任务单轮最多 12 轮、24 次工具调用，保留取消和停止能力。

## 尚存边界

- 能力取决于目标应用公开的 UIA 控件和接口。纯画布、未暴露的菜单、管理员权限隔离等情况不能保证自动完成；本轮未验收全部 47 个应用。
- WPS 无页码接口时，只报告已发送指定页码请求；只有实际能核对的放映出现、退出或控件状态才标记为成功。
- 打开文稿仍可能先发现已有应用窗口，文稿尚在加载时结果会保留为待确认；不宣称所有格式均可立即核验打开成功。
- 关闭文稿遇到未保存提示时保留提示，由用户决定。不自动跳过登录、密码、提交或删除确认。

本地回归通过不等于所有学校电脑已完成验收。安装包与正式服务仍保持原发布状态。

## 2026-10-27 补充：WPS 截图问题与模糊转写

这次按用户原话“能不能打开WPSX啊，做一页PPT写上5个字，这是测试文件”复现并验收。

- WPS 演示由 `wps.exe` 承载时，之前虽然识别了演示类型，却仍返回 WPS 文字的应用编号，导致启动检查误报没有窗口。现在只在同一允许安装目录内关联对应的逻辑应用，保留进程路径校验；未保存的“演示文稿”也可以正确归类。
- 新增 `create_presentation`：使用已观察、允许的 PowerPoint 或 WPS 演示，新建独立的一页文稿并写入原文。创建前核对 COM 安装目录，创建后核对实际页数、正文、字符数及新出现的文稿窗口。保留确认、取消和单次执行回执，不自动保存或修改已有课件。
- 口述字数和明确给出的正文不一致时保留完整正文。上面的文字实际为六个字；结果以读回的正文和字符数为准，不根据“五个字”删去一个字。
- 语音转写后的理解现在明确允许结合上下文及实际应用候选处理同音、近音、缩写和多余字母。原始转写保留，指定正文、数字、否定词、班级、设备和路径不做全局替换；多个合理目标时简短询问。`<unk>` 等真正缺失的内容继续要求重说，不能凭空补全。
- 模型公网解析报错未能稳定复现，本机的 HTTPS DNS 探测曾连续 20 次成功。为短暂断连、超时增加一次有界重试，两次共用原来的约八秒预算；TLS 校验失败、跳转、无效或私网答案不重试。不重发模型请求或电脑修改，不能据此宣称外部网络问题已全部消除。

## 2026-10-27 补充：云端视觉本地试用

班班现在可以将所选允许窗口的实际画面交给现有 DeepSeek `deepseek-flash` 连接，按图片位置点击、输入、按键、拖动和滚动。UIA、文稿接口可以准确完成的任务仍使用原接口；纯画布等需要看图的任务走视觉。使用既有语音对话入口，没有增加面向用户的坐标操作面板。

本地生成截图，云端理解图片，本机执行输入。图片长边最多 1280 像素、编码最多 512 KiB；每个动作自动返回新画面，模型应看图核对实际结果后再继续。图片只在短期内存与本轮模型请求中流转，不写入聊天历史、SQLite、操作回执或产品日志。新截图替换旧截图，不持续上传桌面。只有截图元数据进入审计，卡片不展示截图编号与坐标。

操作绑定账号、设备、班级、实际窗口与最新截图，截图有效期 60 秒且只允许一次输入。窗口尺寸变化、坐标越界、其他窗口遮挡、目标失效会停止输入。保留取消与语音直接执行规则；不会把画面中的文字当成用户的新指令。拒绝密码字段、终端及已列入限制的安全类程序。发送输入的回执只证明动作已送达，不能代替业务成功核对。

参考了 [Microsoft UFO 的窗口截图实现](https://github.com/microsoft/UFO/blob/main/ufo/automator/ui_control/screenshot.py)中的指定窗口捕获、缩放、动作后再观察模式，没有引入该框架或直接复制源码。本轮没有新增依赖或下载视觉模型。相比上一份本地验收编译产物，`ICeClass.dll` 从 434,580,992 字节变为 434,597,888 字节，增加 16,896 字节；这不是安装包体积比较，本轮没有重新制作安装包。
