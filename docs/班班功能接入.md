# 班班功能接入

教师端的业务能力从当前服务已注册的实际路由生成。普通界面和班班调用同一个处理器，权限、参数校验及保存规则保持一致。已有操作编号和历史记录继续可用。

## 新增业务功能

在原业务处理器上声明能力，再按正常方式注册路由，无需修改班班操作清单或工具枚举。

```python
from teacher_capabilities import teacher_action, teacher_read

@teacher_read('example', '查看示例设置', fields='start end')
async def get_example(request):
    ...  # 原有身份验证、权限校验与查询

@teacher_action('example.update', '修改示例设置', fields='value revision',
                roles=('superadmin',), impact='将更新学校设置。')
async def update_example(request):
    ...  # 原有权限、参数、版本检查与保存

app.router.add_get('/api/example', get_example)
app.router.add_put('/api/example', update_example)
```

- 编号必须唯一且稳定。方法、路径和实际处理器由路由读取。
- `fields` 只声明允许传入的字段，不能代替处理器的类型和业务校验。密码、密钥和原始文件不放入模型参数。
- `roles` 限制准备操作时的角色，实际处理器仍须重新授权。班级操作使用 `target='class'`；仅班主任和上级可以修改时增加 `head_only=True`。
- 修改默认需要确认。只有允许直接执行的查询、打开等操作才设置 `confirm=False`。语音沿用原有明确请求规则，私密输入和文件预览仍需要本人完成。
- 涉及可变配置时使用版本号，原处理器负责原子保存与冲突检查。操作不会在后台猜测新配置的数据库结构。

文件下载使用 `workflow='download'`，返回需登录的同源保存入口。当前课表导入使用 `workflow='island-import'`：选择 XLSX、读取预览、核对、确认保存；文件原件不进入聊天或操作历史。绑定码使用 `workflow='private-result'`，只在本人展开确认卡时读取，服务器临时保留五分钟，不写入操作结果。

确实需要现场录音、私密输入或专门设备协议的业务入口，使用 `@teacher_manual('具体原因')`。现有认证、模型私密连接、更新下载及设备传输协议在 `teacher_capabilities.py` 中明确排除，不能以此排除普通新业务。

运行下面的检查，缺少能力声明的新增业务接口会失败，包括新的 API 命名空间：

```powershell
python -m unittest discover -s server -p 'test_teacher*.py'
```

## 教师端本机与页面

原生能力在 `DesktopWindow` 的 `TeacherAction` 注册处声明名称、确认规则和实际方法。网页通过 `ICeClassTeacherHost.catalog()` 获取当前窗口能力；新注册的动作自动进入本轮目录。当前接入桌面设置、关于、反馈、刷新和检查更新。

页面入口从当前账号实际可见的侧栏生成。打开页面复用原导航事件和未保存提示，不直接绕过界面状态。浏览器可使用页面导航；原生功能需要新版教师端。

本机操作只执行本轮实时事件，先原子领取、再执行、最后回报。历史恢复、重复事件和重复领取不会再次执行。同源、主文档、当前登录、窗口编号和操作编号均需核对；登出、页面切换或断连后不自动重试。

“已打开设置/反馈窗口”只代表窗口已打开，保存设置和发送反馈仍由老师在原表单完成。刷新保留原生确认提示；检查更新不会自动安装或重启。结果未确认时不能称为已完成。

## 月度使用次数

超级管理员在“账号设置 → 班班次数”管理默认上限和单独上限，并查看当月用量。教室端按经过绑定认证的设备编号计次；教师端和网页按登录账号计次，同一账号的多个窗口共用额度。教室设备与教师账号分别计算，不从语音目标、请求正文或客户端自报编号推断调用者。更换班主任、新建对话和重启服务不清零用量。

月份按北京时间计算，每月 1 日 00:00 自动使用新月份额度，无需定时清空或重启服务。初始上限为空，表示不限次；0 表示禁止发起新对话和新操作。单独上限可以设为不限次，也可恢复沿用默认上限。修改上限保留当月用量，已用次数达到或超过新上限时阻止新请求。

一次通过校验并开始处理的用户对话计 1 次，包括本地回答、文字和语音。对话中的模型工具调用、后续确认、文件输入和执行回执不重复计次。单独调用班班操作接口的新操作计 1 次，相同 `requestKey` 重复获取同一操作不重复扣次。参数错误、权限不足、忙碌拒绝不计次；开始处理后的失败、取消和网络中断仍保留本次计数。普通业务界面的操作与后台晚自习自动检测不使用这项额度；晚自习 AI 复核继续使用独立预算。

旧版 `/api/banban/chat`、流式对话和单独操作接口都在服务端原子扣次。额度用尽返回 HTTP 429、`code: banban_quota_exhausted`、本人额度及恢复时间；查看历史、取消、明确停止设备操作和已有操作的确认、回执不受限。对话框随现有上下文请求和实时响应显示剩余次数，额度用尽后可手动刷新，不增加常驻轮询。

`GET /api/banban/quota` 只返回本人用量。`GET/PUT /api/banban/quotas` 仅允许超级管理员；保存必须携带当前 `revision`，冲突返回 409，且不覆盖已保存设置。设置、单独上限与月份用量保存在 SQLite 的 `banban_quota_*` 表中，更新经过原有审计。新增设备与账号默认沿用对应上限。

回归检查：

```powershell
python -m unittest discover -s server -p 'test_banban_quota.py' -v
node --test scripts/test-banban-quota.cjs
```

## 本轮验证与人工验收

自动检查覆盖动态发现、权限、重复确认、真实业务处理器、版本冲突、课表导入导出及本机执行回执。真实模型评测使用隔离数据库和虚构数据，本机窗口回执在模型评测中明确标记为模拟；原生桥另有真实 WebView2 检查。真实班级、邮件发送与教室硬件不在这组测试中操作。

本地教师端验收时可以依次尝试“打开创意计划”“查看全校浮岛隐藏规则”“导出通知记录”“打开桌面设置”。修改和导入请使用专门的验收班级，核对目标后再确认。
