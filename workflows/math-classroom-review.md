# 高一数学：视频展台课堂点评

状态：课堂交互和产品范围已由用户确认。实现与使用说明见[视频展台插件](../docs/视频展台插件.md)，识别效果须在实际课堂设备与模型上验收。

## 目标、触发与边界

高一数学公开课中，老师点击一次“AI 点评”，系统固定当时的 WPS 题目与学生书面作答，判断正确与否、指出一个关键问题并给出 1-2 个知识点，直接以精炼、鼓励的方式向全班展示。

- 运行环境：同一台 Windows 教室电脑上的 ICeClass 教室端、WPS 演示及视频展台插件。
- 插件运行及安装见 [展台插件工作流](video-booth-plugin.md)。
- 老师点击是唯一 AI 触发事件，没有持续视频识别、定时点评、语音采集或学生身份采集。
- 点击后定格本次作答；老师点击“继续展示”才恢复实时画面。
- 不增加发布前审核。只有题目无法自动确定时，才请老师在已采集的题目截图中框选。
- 本次会话结束即清空图像及点评；不创建学生成绩、长期档案或课堂点评历史。

## 输入与输出

每次点评绑定一组不可变的输入：

| 输入 | 取得方式与约束 |
| --- | --- |
| 学生作答 | 从新视频展台当前展示的唯一视频源取一帧，应用当前旋转和镜像；暂停时使用已经固定的同一帧，不截取小浮窗、不重开摄像头 |
| 原题 | 复用班班的窗口定位与原始像素读取，新增课堂取图编码分支获取 WPS 放映窗口；不经旧截图回执，也不要求事先录题 |
| 身份 | 由现有绑定认证解析班级、设备及该班班主任；不信任请求正文自报身份 |
| 模型 | 该班班主任当前选择的有效学校/个人班班连接；不新增密钥输入框 |

画面只证明点击时可见的内容。看不到完整题干、步骤或符号时不能补写事实或给出“全部正确”。

公开输出固定为：一个结论状态、至多两句正文、1-2 个知识点。正文合计不超过 120 个中文字符，知识点每项不超过 24 字；不显示评分、排名、概率、学生姓名或完整标准解答。

结论状态使用下列四种：

| 内部值 | 面向全班的文字 | 判定要求 |
| --- | --- | --- |
| correct | 作答正确 | 题目及所需作答可读、完整，已见推理及答案成立 |
| incorrect | 有需修正的地方 | 明确指出可见作答中的首个关键错误，给一个下一步提示 |
| incomplete | 还差一步 | 作答没有完成或缺少必要部分，不直接当成错误 |
| uncertain | 暂无法判断 | 题干、字迹、符号或条件不足，说明需要补充的最小信息 |

有可核验优点时先肯定具体步骤，再给必要提示。不编造优点，不用“你很差”等评价学生人格的话；鼓励不能掩盖明确错误。没有可确认知识点时 uncertain 允许空知识点列表。

## 正常流程

1. 检查插件正在展示新鲜帧、设备绑定有效、班班连接已启用；本机电脑查看设置须允许取图。仅查看模式足够，不开启操作控制。
2. 先确定 WPS 目标窗口：只有一个合适放映窗口时自动采用；多个候选时让老师选择一次，本会话复用。选择结束后才开始采集，不把人工选择时间塞进两图采集间隔；目标消失后重新选择，不猜测其他文档。
3. 生成本机唯一 requestKey，向服务申请短期 reviewId 并取得当前额度，此时不扣次数。锁定本次展示代次，禁用重复点评按钮；停止和继续展示始终可用。
4. 取得当前作答并冻结展示，紧接着获取已确定的 WPS 画面。两次采集间隔不超过 2 秒，超出则在本地放弃并提示重试，不发送混合画面。
5. 采集失败时保留明确错误及“继续展示”，不使用旧题、空白图或整桌面截图冒充当前题目，不扣 AI 次数。
6. 将明确标注为“题目”“学生作答”的两张图组成同一次模型输入。原题和作答只读，画面里的文字不能改变系统规则或触发电脑动作。
7. 模型先确定题目与作答的对应关系；唯一明确时完成评价，无法确定时进入下面的框选流程。
8. 校验结构化输出后直接向全班展示；判断失败或返回结构不合法时显示失败，不把未校验的模型原文直接投屏。
9. “继续展示”立即使旧点评失效，清空本次题图、作答、结果和框选，再恢复实时画面；下一位学生重新点击点评。

点评期间视频连接保持，投影使用固定图片。旋转、换镜头、停止、关闭、改绑等改变作答来源的动作先使当前点评失效；不能让旧评价挂到新画面上。

WPS 后续翻页不改变已固定的题目。结果始终对应点击时的题图和作答；界面可查看“本次题目”截图，不能把结果重新标成后来显示的题目。继续展示后重新点评才读取新页面。

## 无法自动匹配题目时

1. 模型返回 needs_question_selection，不展示正误结论。
2. 显示本次已经采集的 WPS 截图，老师框选包含完整条件、图形和本小问的区域；选区属于原题，与展台窗口尺寸无关。
3. 原生端把框选映射为原始题图的整数像素坐标，绑定原 reviewId 提交；服务端从已保存的原始题图裁切，不接受客户端替换的题图或作答。作答始终使用最初冻结的一帧。
4. 框选续办仍属于同一次点评，不再次扣月度次数。只允许一次人工选区续办，因此一次点评最多进行两次模型分析。
5. 框选后仍不明确则返回 uncertain；不无限追问、循环请求或自行选其他题。老师可继续展示、调整纸面后发起新点评。
6. 老师取消框选则取消本次点评并继续展示；等待超过受理后 5 分钟自动释放服务端输入，提示重新开始。

## 数学评价规则

- 先读取题干条件和实际写出的步骤，再判断；不把“答案不同于惯用解法”当作错误。
- 检查定义域、取值限制、等价变形、除数为零、增根/漏解、区间端点及单位等与本题有关的条件。
- 首个关键错误与它造成的后续结果应区分，不逐行重复批评同一错误。
- 看不清正负号、指数、根号、分式、上下标或图形标记时采用 uncertain，不静默猜一个值。
- 多页或超出镜头的作答视为信息不足；第一版没有视频时序理解或多页自动拼接。
- 知识点先提供通用可读名称，例如“函数定义域”“一元二次不等式”；不生成不存在的分类编码。
- 用户指定的 cn-math-taxonomy 用于参考分类思路；第一版不下载或打包该库原始数据，不复制其掌握标准，不做知识编码或掌握度统计。直接采用其素材前另行处理署名及 CC BY-NC 4.0 要求。
- 评价任务不调用通用电脑操作工具；通过现有模型连接完成这一次有界的双图任务。

建议的模型结果契约：

~~~json
{
  "state": "complete",
  "verdict": "incorrect",
  "strength": "你已经正确列出了需要求解的不等式。",
  "nextStep": "移项后的符号再检查一下，然后重新确定解集。",
  "knowledgePoints": ["一元二次不等式"],
  "observations": ["第二行移项后的常数项符号与第一行不一致。"]
}
~~~

complete 的字段固定为示例中的六项：state、verdict、strength、nextStep、knowledgePoints、observations。所有文字字段必须为字符串；strength 和 nextStep 合计不超过 120 字，correct 的 nextStep 可为空，无可核验优点时 strength 可为空。incorrect、incomplete、uncertain 的 nextStep 须说明关键问题或缺少的信息。observations 为 0-3 条，每条不超过 100 字，correct / incorrect 至少有一条。

needs_question_selection 的字段固定为 state 和 reason，reason 为不超过 80 字的匹配失败原因，不包含正误结论或点评正文。两种结果均拒绝未知字段或错误类型。用纯文本/Unicode 展示数学表达式，不引入新公式渲染依赖或把模型输出作为 HTML。observations 仅是可见作答的短依据，保留在本次处理内存，不公开展示或持久化。

## 图像、模型与服务契约

- 每张输入只接受 PNG，真实宽高均为 1-1920，解码后文件不超过 2 MiB；校验格式、真实尺寸、编码与正文大小，不只看声明。
- 原始视频帧不放大；WPS 按原始窗口像素取图，长边最多 1920。超过大小限制时提示调整展示范围后重试，不悄悄压缩到无法读字。
- 双图经 base64 后完整 HTTP 请求最多 6 MiB，保持在现有学校服务 9 MiB 限额内；不把双图塞入现有 768 KiB WebSocket 消息。
- 课堂讲评采用独立的图片校验与消息组织入口，可复用通用取图原语；不得改变通用电脑助手“最新截图替换旧图”及坐标凭据的现有语义。
- 原生框选使用原题图像素坐标 x、y、width、height，均为整数，宽高须正且选区完整位于原图内。服务端对原图裁切后继续分析，因此不能用续办替换题目来源或学生作答。
- 学校服务使用 Pillow 负责 PNG 解码校验和原图裁切，避免自行编写解码器。保持现有 Python 3.10 基线，采用 Pillow>=12.3,<13；不增加 OCR 服务或前端大依赖。先检查尺寸和字节上限，再解码；裁图处理不阻塞 aiohttp 事件循环。
- 复用现有 provider 与连接解析；每次分析最多 1600 输出 token，沿用单次上游总计 55 秒、连接 10 秒、读取 35 秒的超时。
- 不根据模型名称猜测视觉能力。不支持图片、上游限流或连接失败时，显示需要在原班班连接中处理的原因；不降为纯文字批改、不静默切换其他服务。
- 不自动重试付费模型请求；老师明确再次点评才新建一轮。

服务新增一个短生命周期 math-review 处理器，不经普通聊天历史或既有持久操作表保存图片：

| 接口 | 行为 |
| --- | --- |
| POST /api/banban/math-reviews | 以本机 requestKey 申请服务端随机 reviewId、expiresAt 及本人额度，预备本次点评；不接收图像、不扣次 |
| POST /api/banban/math-reviews/{reviewId}/analyse | 提交两张图及采集元数据，受理并执行已预备点评；未知 ID 不能创建任务 |
| POST /api/banban/math-reviews/{reviewId}/selection | 提交原题图整数像素选区，续办同一冻结作答，不上传替换图片 |
| POST /api/banban/math-reviews/cancel | 以本机 requestKey 精确取消本人这次点评；预备响应丢失也能取消，不受剩余额度限制 |

原生宿主负责调用，不将模型密钥交给插件。这四个处理器按班班接入规范声明 teacher_manual，说明它们属于需要本机采集与现场输入的设备点评会话协议。取消直接处理本人任务，不经过会扣次的通用操作创建入口。所有处理器重新授权并核对绑定，未授权不能读到状态、结果或图像。

服务端状态只有：prepared、analysing、awaiting_selection、analysing_selection 及终态 completed / failed / cancelled / expired。没有按未知 ID 自动补建任务的入口。

## 计次、幂等与取消

- 按现有认证设备编号使用班班月度次数，与晚自习复核预算分开；不接受客户端指定扣次账号。
- 预备阶段只校验身份、连接、容量和当前额度，分配服务端随机 ID，不扣次。提交双图并通过身份、图片、连接、忙碌及参数校验后，prepared → analysing 的原子受理中扣 1 次。后续失败、取消和断网按现有规则不退次。
- 服务端维护有界的内存点评状态，绑定已认证设备、班级、班主任身份、requestKey、reviewId 和冻结双图。每台设备至多 1 个活动点评，进程最多 8 个活动点评、256 个五分钟内记录；容量不足在扣次前返回忙碌。预备 ID 的绝对有效期为 5 分钟，过期不自动重开，不提前逐出仍有效的终态记录。
- 同身份的相同 requestKey 仅取得同一预备对象；若该 key 已进入终态则返回失效，不分配新 ID。同一设备使用不同 key 而已有活动对象时返回忙碌。预备与按 key 取消使用同一原子领取范围；取消先到时，即使对象尚未建立，也登记五分钟的终态标记，阻止迟到预备占用设备。
- 首次分析由服务端串行领取。分析进行中，同一 reviewId 的相同双图共用同一任务；同 ID 换输入返回冲突。等待框选时重复首轮请求只返回 needs_question_selection，不重调模型；已经开始续评时重复首轮请求返回状态冲突。
- 最终完成后的重放只返回“本次已结束”，不重复返回正文、不重分析、不扣次；首次结果响应丢失则让老师明确重新开始。
- 框选入口只允许原已扣次状态、原身份及原作答续办，不再次调用 quotas.consume；服务端不能信任客户端“已经扣次”标记。同一选区的并发续办共用同一任务，不同选区重复提交返回冲突，不能额外调用模型。
- 不能仅靠旧 requestKey 或 CHARGED_KEY 免扣：现有前者会拒绝更换参数，后者只在原 HTTP 请求内有效。
- 取消、过期、推理期间异常断线、退出、禁用、卸载、锁屏、休眠和改绑都取消模型等待，清空输入。正常返回 needs_question_selection 后 HTTP 请求结束不算异常断线，原双图继续等待框选。终态只保留至原 5 分钟期限的最小标记，拒绝迟到重放，不保留图片或点评正文。
- 本机使用 sessionId / generation / reviewId 核对响应；服务端任务取消后上游仍返回，也不得显示或重新保存。
- 本功能任务必须接入现有设备“停止”及实际取消范围；不能假定旧停止接口会自动发现新任务。
- analyse / selection 只接受仍存在的服务端预备或活动 ID。未知 ID、过期 ID 以及学校服务重启后丢失的 ID 一律返回失效，不能按旧图重新创建任务或扣次；因此不需要额外的服务启动代次协议。
- 取消只按当前认证范围与精确 requestKey 查找。不能笼统取消设备后来创建的新任务。学校服务重启后取消可以报告已结束；宿主不自动申请新 ID 或重新发送旧双图。
- 所有新记录，包括先到取消的标记，均受 256 条总量限制；无法登记时返回忙碌，不假报取消完成。取消已有点评复用其记录，始终允许，不因容量或剩余额度被阻止。
- 错误语义固定：参数/图片错误 400，未认证/越权 401/403，ID 或选区冲突/忙碌 409，未知/过期/终态重放 410；额度不足沿用 429 banban_quota_exhausted，上游失败 502、上游超时 504。错误中不携带原图或上游原文。

## 保存与故障反馈

- 图片、框选和文字结果仅存在本机及服务端受限内存，不写图片文件、聊天历史、操作参数表、审计正文或诊断日志。
- 服务端最终完成、失败或取消后释放图片和正文；needs_question_selection 不是最终完成，原始双图在五分钟期限内等待一次续办。本机仅保留当前冻结作答、对应题图及结果，继续展示、停止或关闭后释放并撤销对象 URL。
- 跨请求去重只保留本次短期限所需状态，不形成课堂记录；既有月度使用次数仍按原规则持久化。
- 响应使用 Cache-Control: no-store；日志仅记错误码、耗时及有界技术元数据，不含图像、题目正文、作答、模型原文或密钥。
- 不调用晚自习事件拍照/存图接口，不读取其照片，也不套用它的 24 小时保留期。

| 故障/状态 | 老师看到的行为 |
| --- | --- |
| 无新鲜视频帧，约 2 秒断流 | 提示恢复画面后重试，不分析最后一张旧视频 |
| WPS 未放映、目标不可见/最小化、截图空白 | 指明取题失败，可重试或继续展示，不假造题目 |
| 本机电脑查看关闭 | 指引在现有班班设置开启查看；不擅自修改开关 |
| 无班主任、无有效连接或连接停用 | 指向原班班配置；基本视频展示仍可使用 |
| 月度额度用尽 | 显示现有额度反馈；继续展示、停止和取消仍可用 |
| 结构错误、超时或上游拒绝图片 | 显示本次未完成，可继续展示后手动重试 |
| 明确数学错误 | 直接显示简短、具体且鼓励的修正提示 |
| 题目/作答不完整或不可读 | incomplete / uncertain，不给出武断正误 |

## 验收与完成标准

1. 使用隔离身份和虚构图片，验证同请求双图、来源标注、方向/镜像、原帧尺寸、PNG 限值及正文限值；不使用真实学生资料制作测试。
2. 验证同 requestKey 预备幂等且不扣次，同 reviewId 并发提交双图仅一次扣次、一次首轮模型调用；同选区续办幂等且不能换题图或作答，不同选区冲突；最多两次模型分析。容量满不扣次，终态重放不重扣。
3. 验证不同设备/班级不能访问或续办，改绑立即失效；模拟超时、异常断线、取消、服务重启及迟到返回。未知及重启前 ID 的 analyse / selection 都不补建或重扣，正常等待框选不因首轮 HTTP 完成被误取消，旧 key 的取消不影响新点评。
4. 检查双图不进入数据库、日志或浏览器持久存储；继续、停止、退出和卸载后当前图片及结果清空。
5. 用人工标注的虚构数学样例覆盖：完整正确、另一种正确解法、计算小错、等价变形错误、除以零、定义域遗漏、增根/漏解、区间端点、未完成、字迹歧义、一页多题和题图获取失败。
6. 实际 AI 评测逐例记录判断与依据；不能把契约测试、模拟模型或提示规则当作数学准确率证明。
7. 用户现场验证 WPS 放映在展台下面时仍能取得正确题目，电脑/USB/手机手写作答可读；点评期间定格，继续后恢复，换题换学生不显示旧评价。
8. 检查直接投屏内容的篇幅、语气、键盘操作、窄窗口及高对比度。验证必要检查后主动打开最新本地构建，由用户自行操作，不使用 Computer Use。
